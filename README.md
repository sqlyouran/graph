# Java 旅行规划 Agent 课程项目

本项目用于从零构建一个 Java 旅行规划 Agent。当前章节只建立工程契约，不包含 Java 业务代码或可运行实现。

## 输入契约

一次旅行规划请求至少包含以下信息：

- 出发地
- 目的地
- 出行日期
- 行程天数
- 总预算
- 必去景点
- 每日节奏（例如轻松、适中或紧凑）

信息缺失、冲突或含义不明确时，Agent 应通过多轮对话澄清，不得擅自补全会实质影响行程的条件。

## 数据与事实约束

航班、酒店、景点和天气信息必须来自可追溯的数据源，并保留足以独立核验的来源信息与查询上下文。对于未获取、无法验证或已经过期的数据，必须明确说明其状态，不能猜测或伪造。

## Agent 终态要求

最终实现应支持：

- 多轮修复：针对约束冲突、工具失败和验证问题迭代修正候选方案。
- 独立验证：候选生成与结果验证职责分离，验证过程不依赖生成过程的自我判断。
- 有限停止：为迭代次数、工具调用、耗时或成本设置明确上限，并在达到上限时返回可解释的停止状态。
- 过程观测：记录关键输入、模型与工具调用、数据来源、验证结果、修复过程和停止原因，便于调试与审计。

## 模型调用契约

正式候选方案的生成必须调用阿里云百炼真实模型。测试夹具仅用于自动化测试和可重复验证，不得作为生产或开发运行时的模型回退。当真实模型不可用时，系统必须显式失败或进入受控停止状态，不能用夹具伪装成真实生成结果。

## 非目标

本项目只提供旅行规划与决策辅助，不执行真实预订或支付，也不对航班、酒店、景点等服务的实时库存、价格锁定或可用性作出承诺。任何最终交易均应由用户在相应服务提供方处确认并完成。
