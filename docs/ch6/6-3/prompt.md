做一个课堂演示 demo，让学生亲眼看到四道护栏各自能拦住什么。定位先说清：
只演示效果，放测试目录，不碰 TravelPlanningEngine，不调真实模型，别当最终
代码设计。

机制：Loop 每轮往账本记三笔（Token、耗时、未解决 HARD 问题）；护栏看只读
快照，在每轮开始前回答"还能不能继续"。

四道护栏：
1. 无进展：连续两轮 HARD 失败指纹（规则编号+具体证据排序拼接）一字不差就停；
   证据数字还在变（超预算 1205→320 元）算有进展，不停。
2. Token 预算：下一轮前算"已用 + 预估下轮（上一轮×1.2 向上取整）"，超上限
   不启动。
3. 总时限：同公式，量换耗时。
4. 轮次上限：数到就停，兜底。

要停就报出：护栏代号、原因、证据、给用户的建议。多道同时想停，报信息量最大
的（无进展 > Token > 时限 > 轮次）。首轮直接放行。

课堂画面，关键数字全打印：记完 3200 Token/4000ms 后下轮预估 3840/4800；
C1 证据变化算有进展、C6 两轮一字不差算无进展；场景A 两轮 3200/4000 且 C6
不变 → 第 3 轮前被无进展拦；场景B 三轮 4500/5200/6100 超支递减，但第 4 轮前
15800+7320=23120 超 20000 → 被 Token 拦。
