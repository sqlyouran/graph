继续这个旅行规划项目。现在配置用的是 qwen3.8-flash，我看不见每次模型调用前到底组装了什么。先加一个简单的 PromptDumper，把发送前的内容快照存下来。

要做三件事：
第一，PromptDumper 在调用模型之前执行，把 system 和 user 两个角色的完整内容写到 logs/prompts 目录下，文件名用会话 ID 加轮次，不截断、不省略。文件里用 ROLE 标记保留两个角色的边界。技术重试可能在同一轮再次调用，文件已经存在时用 -2、-3 后缀，不要覆盖第一次记录。
第二，同一个文件末尾追加一份分区报告。分区就四个：指令、约束、历史、画像。每个区报三个数——字符数、估算 token 数、占全长的百分比。估算 token 先用字符数除以一点五再向上取整来粗算，理由是这一步只需要看量级和占比，精确 tokenizer 以后再换。最后再报一行 prompt 总长。
第三，分区靠什么识别：在拼 prompt 的地方插入"### SECTION:INSTRUCTION"这类分隔标记，PromptDumper 按标记切段。别用正则去猜内容属于哪个区，因为猜错了统计就是假的，而假数据比没数据更坏事。

还有几条纪律。落盘失败——磁盘满、目录没权限——一律吞掉异常、只打一行 warn，绝不往上抛，理由是这是观测代码，第七章那条纪律照旧——可观察性不许影响规划流程。确认 logs/prompts 目录已被 gitignore 忽略，因为里面有用户请求，不该进仓库。不要改 TravelPlanningEngine 的规划逻辑；给落盘成功、同轮重试不覆盖、落盘失败不抛异常补测试。顺带说一个现状事实：sessionId 目前不在 PlanGenerationInput 里，想办法让它能在 PromptDumper 处拿到——加字段或沿调用链显式传都行，但测试里必须能拿到。
